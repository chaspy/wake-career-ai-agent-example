# 05_jobs_and_planning

04_recommend_rag からの最終仕上げフェーズ。推薦・求人に加えて「プランニング」表示を実装し、面談用の学習/行動プランを自動生成して見せる体験を足しています。コードはリポジトリ直下（＝完成版）と同じスナップショットです。

## 04 → 05 の主な差分
- **プランニングエージェントの追加 (フロントのみ)**: 推薦と求人の結果を読み取り、学習・行動プランと自己検証チェックを決定論的に組み立てます。`frontend/src/pages/Home.tsx:116-180` の `buildPlanReport` でプロフィールと推薦記事を入力にプランを生成し、`handleRecommend` 内でステージ遷移をログ付きで実行します（同:188-255）。生成結果は「面談用プランボード」カードとして描画します（375-447 行）。
- **進捗モニタにプランニング行を追加**: `AgentActivity` がプランナーのステージ（plan → synthesize → validate → done）を表示し、失敗時のエラーも可視化します。`frontend/src/components/AgentActivity.tsx:3-137`。
- **初期プロフィールを刷新**: サンプルユーザを WAKE Guest（Generalist 5 年）に変更し、興味・スキルもハンズオン文脈に合わせて更新しました。`backend/app/db.py:28-35`。
- **ポート/CORS の最終化**: 完成版のフロントポート 5173 に合わせて allowed_origins を整理。`backend/app/config.py:25-28`。Makefile デフォルトも backend 8089 / frontend 5173 へ統一（リポジトリ直下の `Makefile`）。
- **フォームリセットの簡略化**: プロフィールフォームは key の再マウントで初期値を反映する設計に整理（副作用フックを削除）。`frontend/src/components/ProfileForm.tsx:1-97`。

## 起動手順（最短）
```bash
# リポジトリ直下で（05 はルートと同等の完成版です）
cp .env.sample .env   # OPENAI_API_KEY を入れれば live、空なら fake
make dev              # backend:8089 / frontend:5173

# 初回のみ RAG のベクトルストアを用意
make seed
```
ブラウザを http://localhost:5173 に開いてください。複数フェーズを同時に起動する場合もポート衝突はしません。

## 新しくできること
- おすすめ生成後、自動で「面談用プランボード」が下部に出現。3 つのキャリア方針、Learning/Action の TODO、自己検証チェックを一覧化します（`frontend/src/pages/Home.tsx:375-447`）。
- エージェント活動ログに **プランニング** のステップが追加され、何をしているかが可視化されます（`frontend/src/components/AgentActivity.tsx:42-137`）。
- サンプルプロフィールがより一般的になったため、キー未設定でも「おすすめを取得」をすぐ試せます（`backend/app/db.py:28-35`）。

## 仕組みの要点
- **プランニングはフロントで決定論的に生成**: LLM 呼び出しは行わず、推薦結果とプロフィールから静的ロジックで PlanReport を作成します。ハンズオンで「プランニング層を後付けする」イメージを掴むための疑似エージェントです（`frontend/src/pages/Home.tsx:116-180`）。
- **ステージ制御とログ**: 推薦・求人・プランナーの各ステージを UI ステートで管理し、ログへ時刻付きで記録します。LangGraph の非同期実行を模した見せ方にしています（同:188-260, 335-343）。
- **バックエンドは 04 と同等**: RAG/求人 API と LangGraph の構成は据え置きです（`backend/app/rag/graph.py` ほか）。CORS と初期プロフィールが微調整された程度で、API 互換性は維持しています。
